# Free DNA V6.1 copy → data-basis matrix

Status: implementation and copy-review source of truth
Report contract: `free-dna-report-6.1.0`
Copy contract under review: `free-dna-semantic-copy-6.1.1`

The constitution and storyboard direction were read in full on 2026-08-25.
The storyboard's 33 screens remain a reference arc composed into the existing
nine beats; this matrix never turns them into a fixed page count. Every
headline proposed by the V6.1 story specification is listed below. A
headline may be rendered only when its `required_condition` is true. If it is
not true, the renderer uses the row's neutral or insufficient variant. A mixed
variant is used only when the listed component evidence supports the tension.

The matrix binds editorial copy to existing fields; it does not authorize new
fields, estimators, thresholds, outcome keys, or semantic qualification.

## Matrix columns

- `copy_id`: stable editorial identifier for implementation and review;
- `screen`: reference screen or Element/family surface;
- `headline`: exact Story headline;
- `backend_source`: exact report path(s), Element, family, or outcome;
- `semantic_outcome`: registered key, or `descriptive` for non-finding content;
- `required_condition`: server condition before rendering the headline;
- `evidence_source`: the fields used by Depth 2/3 proof;
- `neutral_variant`: exact narrative when a supported comparison stays compatible;
- `insufficient_variant`: exact narrative when the support contract is not met;
- `mixed_variant`: exact narrative when valid components disagree;
- `forbidden_stronger_interpretation`: the sentence meaning the UI must not add;
- `known_limitation`: the factual boundary shown in Evidence/Methodology.

## D. Copy governance

1. The semantic key, outcome family, denominator, alternatives, verification
   rule, interaction kind, and forbidden tokens remain server-owned.
2. The consumer headline may become shorter and more human only if it preserves
   the exact registered meaning in the row above.
3. A new headline, state variant, or evidence label is a copy-catalog change,
   not a frontend-only change, when it is server-authored or source-bound.
4. No client code may construct a new finding sentence from raw keys, p-values,
   or missing fields.
5. Shadow-only outcomes never receive Story, Signature, share, or Deep copy.
6. The copy review generator must enumerate the same 28 registered outcomes,
   including the three shadow-only records, after any catalog update.
